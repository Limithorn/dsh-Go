## 1. 分组决策

10 项按**职责**归四组，按**配置依赖**排序，全覆盖、无重叠。与 audit 里的编号对应如下。

| 顺序 | 分组 | 参数（audit #） | 控件 | 生效条件 |
|---|---|---|---|---|
| 1 | 声纹开关（总闸） | `voiceprint`(4)、`voiceprintWake`(9) | 开关 | 前者是总闸，恒可用 |
| 2 | 声纹模型 | `voiceprintMic`(3)、`voiceprintLevel`(5)、`voiceprintBias`(6)、`voiceprintOthers`(8) | 胶囊 / 二级页 / 高级 / 开关 | 随总闸 |
| 3 | 声纹录入 | `VoiceProfileSource`(10) | 二级页 | 随总闸 |
| 4 | 通话与采集 | `callMicSource`(1)、`micGain`(2)、`sensitivity`(7) | 二级页 / 按钮 / 胶囊 | 始终生效，独立于声纹 |

**排序原则**：开关在前，下游在后。总闸没开时，模型和录入两组摆在那也没有消费者，所以 `voiceprint` 必须排在它控制的所有组之前。通话与采集是公共底层（打断、唤醒、断句、声纹都吃这条流），不属于声纹依赖链，放在末尾且恒可用。

### 两处纠偏

**`voiceprintMic` 归声纹模型，不归采集**。它确实是 VAD——映射 `silence` → `KaldiFbank.Silence`，判据是能量统计（`percentile / multiple / voicedFraction`）。但 `KaldiFbank` 是**声纹自己的特征提取前端**，这个 VAD 只在声纹链路里被消费；声纹关掉、Fbank 不跑，它就没有消费者。所以：

- 显示名改为「静默检测」，带 VAD 角标，副标题写清"多大声算有人在说"；
- 放进「声纹模型」组，随总闸置灰。原先"不影响识别"的说法是初稿归采集组时的措辞，一并废弃——它就服务于识别。

> 判据是能量统计只说明它**在哪一层生效**（前端），不说明它**属于哪个模块**（声纹）。按数据流位置分类会得出"归采集"的错误结论，初稿即如此，已废弃。

**`sensitivity` 归通话与采集，不归声纹**。它是打断参数，按你的批注本该一直生效、有独立阈值（audit §7、待确认项 B）；虽然现在实现错挂在声纹的 playing 分支上，但那是待修的 bug，不该让布局跟着错。

## 2. 页面骨架

按 [page-design.md](page-design.md) §1 的**详情页（B 类）**：页头 → 分组卡片，无胶囊页签。

- **页头**：标题「语音」+ 一行状态（"通话增强生效中 · 声纹识别未启用"）+ 三个当前值（音源 / 增益 / 插话），数字用 `AppType.tabular`。让人一进来就知道现在什么状态，不用翻每一行。
- **分组**：标题小而淡（tertiary），组间 24，组标题到卡片 8。
- **卡片**：圆角 20，0.5 边框；卡内行间**不画线**，靠行高与留白；单行 52、两行 64。
- **控件**：档位少用 `SegmentedPill` 直接平铺；档位多或有副作用说明用二级页；开关用原生。窄屏（360dp / 字号 1.3）放不下时胶囊换行到标题下方，不折成竖排。
- **一屏一个重心**：页头三值区之外不出现主色实心块；VAD 角标是唯一的强调色文字。

> 页面路径：设置首页 › 通用 › 语音识别。设置首页那一行右侧显示当前值（如"通话 · 标准"）。

## 3. 逐行规格

### 声纹开关 · 总闸

| 行 | 控件 | 默认值 | 副标题 |
|---|---|---|---|
| 声纹识别 | 开关 | `false` | 通话时只认本人的声音 |
| 唤醒声纹 | 开关 | `false` | 唤醒也走声纹判定 |

排在页面最前。后者是前者的子项，前者关闭时置灰。唤醒是常开监听、判定次数远多于通话，所以保留独立开关（audit §9）。

### 声纹模型 · 随总闸

| 行 | 控件 | 档位 | 副标题 |
|---|---|---|---|
| 静默检测 `VAD` | 三档胶囊 | normal / quiet / faint | 多大声算「有人在说」 |
| 判定门槛 | 二级页单选 | loose / normal / strict / very_strict | 声纹相似度基线 |
| 他人打断 | 开关 | `true` | 旁人说话也算打断 |
| 高级 · 门槛微调 | 二级页 | −0.20 ~ +0.20 | 调试用 |

- 静默检测是声纹特征前端的 VAD（`KaldiFbank.Silence`），随总闸置灰；副标题去掉"不影响识别"的说法——它就服务于识别。
- 判定门槛的二级页放三闸数值表（BARGE / WAKE / TURN），并注明"多人时自动抬高"。
- `voiceprintBias` 不进主屏：它能直接把一档调成另一档（±0.20 > 档间 0.10），是调试参数（audit §6、待确认项 A）。

### 声纹录入 · 随总闸

| 行 | 控件 | 档位 | 副标题 |
|---|---|---|---|
| 录入音源 | 二级页单选 | call（默认）/ wake / raw / unprocessed | 需与通话音源一致，否则分数掉 |

这一项不在 `CallSettings` 里（存在每个 `VoiceProfile`），但用户心智上属于语音设置，收进本页单独成组，排在声纹模型之后、随总闸。

### 通话与采集 · 始终生效

| 行 | 控件 | 值 / 档位 | 副标题（用户可见） |
|---|---|---|---|
| 麦克风音源 | 二级页单选 | `communication`（默认）/ `recognition` / `auto` | 自动检测约等 4.5 秒 |
| 麦克风增益 | 数值 +「量一下」按钮 | 1.0 ~ 32.0，默认 1.0 | 采集后放大倍数 |
| 插话灵敏度 | 三档胶囊 | 灵敏 / 谨慎 / 标准（默认） | — |

- 这一组是公共底层，独立于声纹总闸——声纹关掉后，打断、唤醒、断句仍要走这条流，所以恒可用。
- 音源二级页每个档位写清副作用：通话带 AEC/NS 但可能压人声；识别电平高但回声会漏；自动要量两路 1.5s。
- 增益「量一下」沿用现有 3 秒测量流程（`speech_settings.dart`）。

## 4. 联动与默认值

**联动矩阵**（✓ 可用，— 置灰）：

| 组 | 声纹识别开 | 声纹识别关 |
|---|---|---|
| 声纹识别（总闸） | ✓ | ✓ |
| 唤醒声纹 | ✓ | — |
| 声纹模型（含静默检测） | ✓ | — |
| 声纹录入 | ✓ | — |
| 通话与采集 | ✓ | ✓ |

**默认值改动**：`callMicSource` 从 `auto` 改为固定 `communication`。理由：auto 实测验证阶段卡约 4.5 秒（audit 批注 1 / 待确认项 E），体验代价大；把自动档留在二级页供需要时手动切，符合"默认稳、进阶可选"。

> 联动只改可用性与默认值，不改底层配置结构——10 个参数仍各自独立存储。

## 5. 批注项的落地

| 待确认项 | 设计侧的回应 |
|---|---|
| A bias 能覆盖一档差 | 沉入「高级 · 门槛微调」，不与普通门槛并列 |
| B sensitivity 只在播放时生效 | 归到「通话与采集」，文案按打断参数写；代码侧仍要拆出独立阈值（设计只负责归位） |
| C 两套音源枚举 | 录入音源副标题明示"需与通话音源一致"；真正的枚举对齐在代码侧 |
| D voiceprintMic 与 micGain 不冲突 | 两者不同层：前者归声纹模型、后者归采集组，自然分开；文案不暗示因果 |
| E auto 音源测 4.5 秒 | 默认固定 `communication`，自动档移入二级页并写明耗时 |
| F voiceprintLevel 数值待重标定 | 二级页放三闸数值表，标定完成后只改表，不动布局 |

## 6. 需要拍板与不做

**需要拍板**：

1. `voiceprint` 当前默认 `false`（audit §4）——本设计沿用。但默认关闭时"怎么打断"需要产品给一个明确答案：是走纯能量闸，还是把 `sensitivity` 提升为默认打断方式。
2. 判定门槛四档的数值是否按实测重标定后再上线（影响二级页那张表）。
3. `sensitivity` 的 bug 修复（B 项）是否与本页改版同批——若不同批，页面上的归位会先于代码生效。

**不做**：

- 不在本页放声纹录入的录音流程（模板注册是独立流程，本页只有音源选择）。
- 不改 10 个参数的底层字段名与存储位置——改名只发生在显示层（如 `voiceprintMic` 显示为「静默检测」）。
- 不合并 `callMicSource` 与 `VoiceProfileSource` 两个枚举——它们是两条链路，设计上只做提示，对齐在代码侧。
